Bro, we need to construct two monthly datasets and then combine them into our final member-month dataset.

All queries below are read-only. No tables will be created, modified or published.

1. Build the monthly eligible banking population

Period: October 2025 to October 2026 (13 month-end snapshots).

SELECT DISTINCT
    D.POP_DATE,
    D.MEMBER_ID,
    D.ACTIVE_IND,
    F.CURRENT_BANKPROD_CNT
FROM CUSTOMER_DEMO D
INNER JOIN MEMBER_FEATURES F
    ON D.MEMBER_ID = F.MEMBER_ID
    AND D.POP_DATE = F.POP_DATE
WHERE D.POP_DATE BETWEEN '2025-10-31' AND '2026-10-31'
    AND D.POP_DATE = LAST_DAY(D.POP_DATE)
    AND D.ACTIVE_IND = 1
    AND F.CURRENT_BANKPROD_CNT >= 1
    AND D.MEMBER_ID IS NOT NULL;

Purpose: Construct the eligible banking population as of each month-end.

Expected structure:

POP_DATE	MEMBER_ID	ACTIVE_IND	BANKPROD_CNT
2025-10-31	101	1	2
2025-10-31	102	1	3
2025-11-30	101	1	2
2025-11-30	102	1	3

Assuming approximately 10M members per month, we will have around 130M member-month records.

2. Build the monthly task activity dataset

Period: November 2024 to October 2026 (24 months).

SELECT
    LAST_DAY(TASK_DATE) AS TASK_MONTH,
    MEMBER_ID,
    1 AS MONTHLY_TASK_FLAG
FROM TASK_ACTIVITY
WHERE TASK_DATE >= '2024-11-01'
    AND TASK_DATE < '2026-11-01'
    AND MEMBER_ID IS NOT NULL
GROUP BY
    LAST_DAY(TASK_DATE),
    MEMBER_ID;

Purpose: Reduce the large task dataset to one row per member per month in which they completed at least one task.

Expected structure:

TASK_MONTH	MEMBER_ID	MONTHLY_TASK_FLAG
2024-11-30	101	1
2024-12-31	101	1
2025-06-30	102	1
2025-11-30	103	1

We don’t need to generate records for months without tasks. Those will be handled when we join with our base population.

3. Join both datasets and create the 12-month task flag

Instead of joining every member to 12 months of task records, we can use Snowflake’s ASOF JOIN to identify the most recent task-active month on or before each population date. This also retains members without matching task activity. Snowflake Documentation

WITH BASE_POP AS (
    SELECT DISTINCT
        D.POP_DATE,
        D.MEMBER_ID,
        D.ACTIVE_IND,
        F.CURRENT_BANKPROD_CNT
    FROM CUSTOMER_DEMO D
    INNER JOIN MEMBER_FEATURES F
        ON D.MEMBER_ID = F.MEMBER_ID
        AND D.POP_DATE = F.POP_DATE
    WHERE D.POP_DATE BETWEEN '2025-10-31' AND '2026-10-31'
        AND D.POP_DATE = LAST_DAY(D.POP_DATE)
        AND D.ACTIVE_IND = 1
        AND F.CURRENT_BANKPROD_CNT >= 1
        AND D.MEMBER_ID IS NOT NULL
),
MONTHLY_TASKS AS (
    SELECT
        MEMBER_ID,
        LAST_DAY(TASK_DATE) AS TASK_MONTH
    FROM TASK_ACTIVITY
    WHERE TASK_DATE >= '2024-11-01'
        AND TASK_DATE < '2026-11-01'
        AND MEMBER_ID IS NOT NULL
    GROUP BY 1, 2
),
COMBINED AS (
    SELECT
        B.*,
        T.TASK_MONTH AS LAST_TASK_MONTH,
        CASE
            WHEN T.TASK_MONTH >
                 DATEADD(MONTH, -12, B.POP_DATE)
            THEN 1
            ELSE 0
        END AS TASK_FLAG_12M
    FROM BASE_POP B
    ASOF JOIN MONTHLY_TASKS T
        MATCH_CONDITION(B.POP_DATE >= T.TASK_MONTH)
        ON B.MEMBER_ID = T.MEMBER_ID
)
SELECT
    *,
    CASE
        WHEN TASK_FLAG_12M = 1 THEN 'POP 1'
        ELSE 'POP 2'
    END AS TASK_POPULATION
FROM COMBINED;

Purpose: Create the final monthly dataset containing the eligible banking population and its task-based population classification.

4. Expected final dataset

POP_DATE	MEMBER_ID	Bank products	Last task month	12M flag	Population
Oct-25	101	2	Sep-25	1	Pop 1
Oct-25	102	3	Nov-24	1	Pop 1
Oct-25	103	1	NULL	0	Pop 2
Nov-25	101	2	Sep-25	1	Pop 1
Nov-25	102	3	Nov-24	0	Pop 2
Nov-25	103	1	Nov-25	1	Pop 1

Notice how:

* Member 101 remains in Pop 1.
* Member 102 moves from Pop 1 to Pop 2.
* Member 103 moves from Pop 2 to Pop 1.

5. Validate monthly population counts

Once you have the above query, replace its final SELECT statement with:

SELECT
    POP_DATE,
    COUNT(*) AS TOTAL_ROWS,
    COUNT(DISTINCT MEMBER_ID) AS BASE_POPULATION,
    COUNT_IF(TASK_FLAG_12M = 1) AS POP_1,
    COUNT_IF(TASK_FLAG_12M = 0) AS POP_2,
    ROUND(
        100.0 * COUNT_IF(TASK_FLAG_12M = 0)
        / COUNT(*), 2
    ) AS POP_2_PCT
FROM COMBINED
GROUP BY POP_DATE
ORDER BY POP_DATE;

Illustrative numbers.

Before execution, verify three assumptions:

* Both banking tables have historical month-end snapshots.
* Both banking tables have consistent, unique member-date records. DISTINCT alone won’t resolve conflicting product counts.
* The task table contains completed tasks across all relevant categories and channels with consistent historical coverage.

I would complete these five steps first. After validating the monthly population counts, we can write the migration queries. Transactions can be added later using the same structure.
