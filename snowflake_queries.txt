Below are the Snowflake queries in execution order.

Assumptions: MEMBER_ID, POP_DATE and CURRENT_BANKPROD_CNT exist. Replace table names and illustrative Consumer Lending columns with your actual schema.

1. Set the population date

SET POP_DT = '2026-11-22';

Purpose: Use the same population snapshot date across queries.

2. Check distinct members in both tables

SELECT
    'CUSTOMER_DEMO' AS SOURCE,
    COUNT(*) AS TOTAL_ROWS,
    COUNT(DISTINCT MEMBER_ID) AS DISTINCT_MEMBERS
FROM DB_NAME.SCHEMA_NAME.CUSTOMER_DEMO
WHERE POP_DATE = TO_DATE($POP_DT)
UNION ALL
SELECT
    'MEMBER_FEATURES' AS SOURCE,
    COUNT(*) AS TOTAL_ROWS,
    COUNT(DISTINCT MEMBER_ID) AS DISTINCT_MEMBERS
FROM DB_NAME.SCHEMA_NAME.MEMBER_FEATURES
WHERE POP_DATE = TO_DATE($POP_DT);

Purpose: Check total records and distinct members for the same date.

3. Check banking product distribution

SELECT
    CURRENT_BANKPROD_CNT,
    COUNT(DISTINCT MEMBER_ID) AS DISTINCT_MEMBERS
FROM DB_NAME.SCHEMA_NAME.MEMBER_FEATURES
WHERE POP_DATE = TO_DATE($POP_DT)
GROUP BY 1
ORDER BY 1;

Purpose: Understand how many members have 0, 1, 2, 3 or more banking products.

4. Check duplicate member-date records

SELECT
    MEMBER_ID,
    POP_DATE,
    COUNT(*) AS RECORD_COUNT
FROM DB_NAME.SCHEMA_NAME.MEMBER_FEATURES
WHERE POP_DATE = TO_DATE($POP_DT)
GROUP BY 1, 2
HAVING COUNT(*) > 1
ORDER BY RECORD_COUNT DESC;

Purpose: Check whether MEMBER_FEATURES contains multiple records per member on the same date. Repeat for CUSTOMER_DEMO by changing the table name.

Resolve duplicates before creating the base population.

5. Check member overlap between tables

WITH DEMO AS (
    SELECT DISTINCT MEMBER_ID
    FROM DB_NAME.SCHEMA_NAME.CUSTOMER_DEMO
    WHERE POP_DATE = TO_DATE($POP_DT)
),
FEATURES AS (
    SELECT DISTINCT MEMBER_ID
    FROM DB_NAME.SCHEMA_NAME.MEMBER_FEATURES
    WHERE POP_DATE = TO_DATE($POP_DT)
      AND CURRENT_BANKPROD_CNT > 0
)
SELECT
    COUNT_IF(D.MEMBER_ID IS NOT NULL
         AND F.MEMBER_ID IS NOT NULL) AS MATCHED_MEMBERS,
    COUNT_IF(D.MEMBER_ID IS NOT NULL
         AND F.MEMBER_ID IS NULL) AS DEMO_ONLY,
    COUNT_IF(D.MEMBER_ID IS NULL
         AND F.MEMBER_ID IS NOT NULL) AS FEATURES_ONLY
FROM DEMO D
FULL OUTER JOIN FEATURES F
    ON D.MEMBER_ID = F.MEMBER_ID;

Purpose: Identify the intersection of demographic members and members with at least one banking product, plus unmatched members.

6. Create the base population

CREATE OR REPLACE TABLE DB_NAME.SCHEMA_NAME.CL_BASE_POP AS
SELECT
    D.MEMBER_ID,
    D.POP_DATE,
    F.CURRENT_BANKPROD_CNT
FROM DB_NAME.SCHEMA_NAME.CUSTOMER_DEMO D
INNER JOIN DB_NAME.SCHEMA_NAME.MEMBER_FEATURES F
    ON D.MEMBER_ID = F.MEMBER_ID
   AND D.POP_DATE = F.POP_DATE
WHERE D.POP_DATE = TO_DATE($POP_DT)
  AND F.CURRENT_BANKPROD_CNT > 0
  AND D.MEMBER_ID IS NOT NULL;

Purpose: Create the initial eligible banking-product population.

This assumes both source tables have unique member-date records. Add the validated active-member status condition when its column and meaning are confirmed. No historical digital-activity requirement is applied.

7. Validate the created population

SELECT
    COUNT(*) AS TOTAL_ROWS,
    COUNT(DISTINCT MEMBER_ID) AS DISTINCT_MEMBERS,
    MIN(CURRENT_BANKPROD_CNT) AS MIN_BANK_PRODUCTS,
    MAX(CURRENT_BANKPROD_CNT) AS MAX_BANK_PRODUCTS
FROM DB_NAME.SCHEMA_NAME.CL_BASE_POP;

Purpose: Confirm the resulting population size, uniqueness and banking-product filter.

8. Profile the Consumer Lending table

DESCRIBE TABLE DB_NAME.SCHEMA_NAME.CONSUMER_LOAN;

Purpose: Identify the loan ID, ownership/status fields, balances, product types, dates and available features.

If POP_DATE exists:

SELECT
    COUNT(*) AS TOTAL_LOAN_ROWS,
    COUNT(DISTINCT MEMBER_ID) AS DISTINCT_CL_MEMBERS
FROM DB_NAME.SCHEMA_NAME.CONSUMER_LOAN
WHERE POP_DATE = TO_DATE($POP_DT);

Purpose: Understand Consumer Lending coverage for the same snapshot date.

9. Aggregate Consumer Lending features to member level

Assuming the loan table contains one row per loan per POP_DATE, with the illustrative columns shown:

CREATE OR REPLACE TABLE DB_NAME.SCHEMA_NAME.CL_MEMBER_FEATURES AS
SELECT
    MEMBER_ID,
    POP_DATE,
    COUNT(DISTINCT LOAN_ID) AS TOTAL_CL_LOANS,
    COUNT(DISTINCT CASE
        WHEN LOAN_STATUS = 'ACTIVE'
        THEN LOAN_ID
    END) AS ACTIVE_CL_LOANS,
    SUM(CASE
        WHEN LOAN_STATUS = 'ACTIVE'
        THEN OUTSTANDING_BALANCE
        ELSE 0
    END) AS TOTAL_CL_OUTSTANDING
FROM DB_NAME.SCHEMA_NAME.CONSUMER_LOAN
WHERE POP_DATE = TO_DATE($POP_DT)
GROUP BY MEMBER_ID, POP_DATE;

Purpose: Convert loan-level records into member-level CL features without duplicating members.

Replace LOAN_ID, LOAN_STATUS and OUTSTANDING_BALANCE with actual columns and verify the status codes. If the loan table uses effective dates rather than POP_DATE, use a historical as-of join instead.

10. Add Consumer Lending features to the base population

CREATE OR REPLACE TABLE DB_NAME.SCHEMA_NAME.CL_FINAL_POP AS
SELECT
    A.*,
    CASE
        WHEN COALESCE(B.ACTIVE_CL_LOANS, 0) > 0
        THEN 1
        ELSE 0
    END AS CL_PRODUCT_FLAG,
    COALESCE(B.TOTAL_CL_LOANS, 0)
        AS TOTAL_CL_LOANS,
    COALESCE(B.ACTIVE_CL_LOANS, 0)
        AS ACTIVE_CL_LOANS,
    COALESCE(B.TOTAL_CL_OUTSTANDING, 0)
        AS TOTAL_CL_OUTSTANDING
FROM DB_NAME.SCHEMA_NAME.CL_BASE_POP A
LEFT JOIN DB_NAME.SCHEMA_NAME.CL_MEMBER_FEATURES B
    ON A.MEMBER_ID = B.MEMBER_ID
   AND A.POP_DATE = B.POP_DATE;

Purpose: Enrich the entire banking population with Consumer Lending ownership and additional loan features.

Important: The LEFT JOIN retains members without Consumer Lending products. A zero balance for a member without an active loan is a modeling convention; missing source balances may need separate handling.

11. Final population validation

SELECT
    COUNT(*) AS TOTAL_ROWS,
    COUNT(DISTINCT MEMBER_ID) AS DISTINCT_MEMBERS,
    COUNT_IF(CL_PRODUCT_FLAG = 1)
        AS MEMBERS_WITH_CL,
    COUNT_IF(CL_PRODUCT_FLAG = 0)
        AS MEMBERS_WITHOUT_CL,
    COUNT_IF(CURRENT_BANKPROD_CNT <= 0)
        AS INVALID_BANK_PRODUCT_MEMBERS
FROM DB_NAME.SCHEMA_NAME.CL_FINAL_POP;

Purpose: Validate final member counts, CL ownership distribution and inclusion criteria.

Finally, compare the final population size against the original base:

SELECT 'BASE' AS SOURCE, COUNT(*) AS MEMBERS
FROM DB_NAME.SCHEMA_NAME.CL_BASE_POP
UNION ALL
SELECT 'FINAL' AS SOURCE, COUNT(*) AS MEMBERS
FROM DB_NAME.SCHEMA_NAME.CL_FINAL_POP;

Expected result: BASE and FINAL should have identical row counts if the enrichment table contains at most one record per member-date.

Final dataset structure:

MEMBER_ID | POP_DATE | CURRENT_BANKPROD_CNT | CL_PRODUCT_FLAG | TOTAL_CL_LOANS | ACTIVE_CL_LOANS | TOTAL_CL_OUTSTANDING

This establishes the population for one snapshot. For historical model training, repeat the logic using point-in-time member and loan information rather than joining today’s current features to older dates.
